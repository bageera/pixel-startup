# Changelog

All notable changes to **Pixel Startup** (formerly "Pixel Office"; the visual environment keeps that name) are documented here.
Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions follow [SemVer](https://semver.org/).

## [1.6.0] - 2026-11-23 (HEAD = c3d42cf)

### Added
- **Chief/owner dispatch (G36-4):** the Chief panel gains a task Dispatch row (worker select populated with server-verified binding ids, objective, optional plan review) that stores + dispatches through the real capability chain (`POST /api/v1/capabilities/execute` `delegate.<harness>.task`); rows persist before dispatch, dispatch is audited, and failures stay honest (B1 gateway-offline cancels). Supporting: `/api/v1/office/state` ships each grant-holding worker's verified `binding_id`; malformed delegations answer an honest 400 (executor re-raises `DelegationFailure`, route maps it — with test); the tasks strip renders the verbatim status counts incl. `cancelled`/`planning`.

## [1.5.0] - 2026-11-23 (HEAD = 8134f61)

### Added
- **Chief-of-Staff assignment + task visibility (G36-3):** the dashboard Chief panel gains an agent-to-harness assign form (worker id/name/harness — posts the existing owner-only `/api/v1/office/onboard`; re-submitting the same worker id moves it to the chosen harness; grants `delegate.<harness>.task` + `email.check`/`email.read`) and a tasks strip (counts + 5 newest active rows from `GET /api/v1/office/state`). No backend change.

## [1.4.0] - 2026-11-23 (HEAD = 7d7b9af)

### Added
- **Agent email access + a real OpenClaw execution surface:** the office's INBOX reading moves off the legacy node proxy into python (`integrations/email_read.py`, provider `comms_email_read`). The same IMAP/SSH transport contract as `email.js` (direct IMAP when `EMAIL_IMAP_HOST` is set, otherwise the mail host over SSH), the SAME env account contract (generic `EMAIL_DOMAIN` + per-account password keys), and two G10 capabilities — `email.check` (inbox summary) and `email.read` (single message body, read-only BODY.PEEK) — with owner routes `GET /api/v1/email/accounts|check|message`. An onboarded, verified-bound harness employee granted `email.check`/`email.read` can now check mail through `POST /api/v1/capabilities/execute` (verified live: authorized call → honest not-configured result inside the executor boundary; replayed by request_key; ungranted employees denied). OpenClaw's harness adapter is no longer a stub: `task.submit` executes through the gateway's documented OpenAI-compatible `/v1/chat/completions` surface (single-turn, synchronous, model from payload/env/first-listed; offline cancels B1 honestly), `task.result` returns the recorded execution, and the WS-only operations stay explicitly unsupported. The `delegate.openclaw.task` capability now actually exists.

## [1.3.0] - 2026-11-23 (HEAD = 78699f0)

### Added
- **Privacy: user/host data abstracted out of the tracked JS.** `email.js` ships generic demo accounts (`owner@…` on `EMAIL_DOMAIN`, default `example.com`) with ids/colors/categories intact and passwords still env-driven; `vault.js` tracks no default host, user or Vaultwarden URL; the node morning-briefing prompt (`server.js`) now describes the org by role (business entities, mail host, tracker, infrastructure) instead of listing real addresses, hostnames, LAN IPs, message counts, project names or financial figures; `LITELLM_API_URL` gets no tracked default (`unset = AI offline`, honestly). Real values flow in through env/`pixel-secrets`. See README for the env keys.
- **G33 — Office of Requirement (procedural office architecture):** the office materializes from organizational truth instead of being hand-designed. Three layers (`graph/office_gen.py`): topology resolution from REAL state (CHO, registered/connected harnesses from the adapter probes, workers with actual assignments — existence never mints furniture), a deterministic incremental staged layout (Stage 1 CHO office + harness stations with honest online/offline states; Stage 2 personal stations only for assigned workers; Stage 3 cap-split overflow rooms and floor-2 listings when the walkable grid runs out; append-stable ordering so one new worker never shuffles the building), and theme interpretation (garage/subbasement/firehouse mapping to existing environment assets — same topology, three imaginative readings). Owner API: `GET /api/v1/office/layout` (ETag on the layout key — generation happens only when structure changes, never per frame; zero LLM), `POST /api/v1/office/layout/apply` (materializes floor-1 rooms into the live office; floors 2+ are listed, not stretched), `POST /api/v1/office/layout/theme`. Dashboard Chief panel gains the theme selector + Grow office button; the office page now prefers the materialized server layout over the painted cache. Physical growth (assignments) changes the environment; operational growth (task completions) does not — the layout key is structure-only.
- **Chief communication channels on the dashboard:** the admin dashboard gains a permanent Chief panel (harness + channels) with GET/POST `/api/v1/chief/channels` (owner auth): `office chat` always on, Mattermost/email selectable and honestly labeled "not configured" until live G13 creds exist; unknown channel names are dropped, `startup.chief_channels` persists through full config saves, and the chief prompt receives per-channel configured state — it refuses to claim delivery through any channel that is not live.
- **Chief of Staff harness toggle:** the office chat panel gains a "Chief of Staff" selector (Director / Hermes / OpenClaw, persisted via the owner config channel as `startup.chief_harness`). With a harness selected, chat prompts run in chief mode: the answer is grounded ONLY in observed state — the harness adapter's live `gateway.health` probe and the real task table (roster + task rows included verbatim) — so it evaluates feasibility, reports completed/in-flight tasks, and names the next delegation step without ever claiming work started that no row shows. Movement commands stay the strict-JSON Director when no chief is selected.
- **AI Director chat + status migrated off the Node proxy:** native `/api/ai/chat` + `/api/ai/status` routes (audited LiteLLM provider path, owner-session/kiosk parity, 502-on-down, server-owned nav JSON contract with room fallback); office chat commands ("Tell Charon to go to the Archives", "everyone to ...") live again; dead client-side system prompt removed. UI: office chat-panel tabs are icon-only (labels stay as tooltips + sr-only for a11y/EN-ES).
- **G32-D/E/F economic qualification:** deterministic stress tiers S1–S4 (fixtures 235→213k records) prove visible components stay flat (26→33) and scene payload ~5 KB as records grow ×900; two quadratic hotspots fixed (per-blocker edge-index rebuild in dependency_impact, per-iteration component rescan in the scene attention loop — S3 compose 1,715→93 ms); resource-budget table with measured evidence (routes 14–21 ms, static 0-draw idle, 304 recompose skip); graceful-degradation ladder proven presentation-only (no server lite fork, byte-equal manifests). S4 soak env-gated via PIXEL_STRESS_S4=1.
- **G32-A (renderer extraction + feature flag):** `assets/office-render.js` owns the office frame loop, a cached static environment layer (rebuilt only on background src change — one `drawImage` per draw replaces a full background re-blit) and the manifest-driven org overlay behind `startup.scene_components` (no-erase boolean in the startup config; owner-session required; flip+restore verified live). Visible behavior unchanged; two live-found defects fixed in-commit (silent loop death on renderer error — now logs once and keeps scheduling; static layer tracking background src, not object identity).
- **G32-B/C (bounded rendering + drill-down completion):** pixel-lite/reduced-motion = static (zero idle frames, measured + node-tested); visibility return marks dirty; `framePolicy.stats().samples` is a lifetime tick counter (ring-cap probe misread fixed, suite-pinned). Dashboard Office Scene chips are clickable: organization → project → task evidence via one delegated handler reusing the graph cache. Server: capability chips bounded (30 → 10 + summary, tested), dense-scene placement collisions resolve deterministically, scene ETag identity includes policy+scope (a CHO policy flip can never answer 304 for a changed scene — tested).
- **G32-B/C (office frame policy + bounded scene view):** `assets/office-loop.js` (CommonJS + `window.PixelLoop`, 7-assert node suite in `npm test`) caps full canvas redraws — 33 ms while a character travels, 100 ms ambient for cosmetic wander, 200 ms on `.pixel-lite`/reduced-motion, `dirty` bypasses — while character logic keeps its exact original per-tick cadence (movement speed unchanged). The loop now measures itself (`framePolicy.stats()` p50/p95/max over the last 240 rAF gaps, `window.__pixelDraws` counter); CDP-measured idle full redraws drop 32→14 per 2 s in the same environment. The dashboard gains an **Office Scene** tab: the `/api/v1/scene` manifest rendered as bounded static SVG chips (schema v1, state ETag + 304, unknown types and aggregates skipped per the G31-G contract) — no canvas, no timers, redraw only on fetch.
- **G31 Phase 2 (health dimensions, CHO resolver, scene manifest):** `dimensions()` adds three independent, evidence-backed projections — execution (per commitments), attention (required/waiting/clear from the responsibility model), outcome (**only** `evidence` edges prove results; completed work without outcome records is *unproven*, and a negative result with evidence counts as evidence, never failure). Five health states with tested rules: `blocked`, `waiting-external`, `recovering` (unpause stamps `resumed_at`), `stable`, `unknown`, each with a shape-distinct 16×16 sprite and a deterministic generator. `GET /api/v1/scene` (versioned manifest, schema v1, state ETag + 304): the CHO-mode resolver — curious surfaces idea seeds, focused summarizes them, driven adds bounded decision stations with impact counts; capability components are `verified | suggestion | unavailable` (never fabricated availability); layout positions derive from node ids so minor updates never rearrange the scene; 50 projects render as 10 workstations + one count summary; household scope never leaks. Zero LLM asserted across graph/scene/impact reads.
- **G31 Phase 1 (census, truth model, attention, dependency impact):** measured repository baseline (`docs/g31-baseline.md` — office renders a full scene redraw ~16 fps idle on one 2d canvas; graph API 21–55 ms; no WebGL anywhere). Schema v7 extends the organizational vocabulary (decision/commitment/contact/capability/outcome) with an `owner_role` (cho/employee/client/vendor/external) and `soft_depends` edges — migration rebuilds the graph tables from staging copies and preserves all rows (tested). `attention()` gives responsibility-aware states: CHO/employee overdue commitments become actionable-overdue, client/vendor/external silence is only `waiting` (never a failure), explicit follow-up policies (`days`/`business_days`) create follow-up opportunities at threshold, paused work is dormant, unknown data stays unknown. `GET /api/v1/graph/impact` surfaces a shared blocker ONCE with direct/downstream-affected counts and soft-dep scheduling risks — separate outputs, cycle-safe, scope-isolated. Zero LLM calls maintained (tests assert).
- **Living Startup environment (G30):** organizational graph in SQLite v6 (organization/goal/idea/project/milestone/task; depends_on/related/evidence edges; stable ids; company/household scope isolation; idempotent, cycle-guarded edges via `POST /api/v1/graph/edges`). Deterministic health projection (`src/pixel_startup/graph/health.py`, zero LLM calls — asserted): seed/growing/thriving/needs-attention/withering/dormant/completed/archived, each with a human explanation; deadline-free ideas never rot, paused work never deteriorates, completed work never rots, blockers are named. `docs/g30-living-startup.md` carries the API. Dashboard gains a **Living Startup** tab: lazy-opened (data + sprites only when the view opens), SVG mind map with pan/zoom/drag, persistent branch collapse, select→detail panel, stalled-work panel, plant-seed form, connect-related form, CHO-policy (`startup.mood`: curious/focused/driven) banner — view preferences, not separate data models.
- **Resource discipline (G32):** `GET /api/v1/graph` answers a state-summarizing ETag + **304** to `If-None-Match` (frontend reuses the tag; unchanged state = zero payload, zero re-render), and both frontends degrade gracefully — `prefers-reduced-motion` collapses animation and constrained devices (`hardwareConcurrency`/`deviceMemory`) get a `.pixel-lite` mode that drops animation/filters before informational fidelity. Full table + design evidence in `docs/g32-resource-discipline.md`.
- **MinIO connected + real SigV4 (G29):** storage provider probe (HEAD bucket) promotes the minio row at boot, and every startup appends one JSONL access-log line to `shared/access-logs/<date>.jsonl` (storage down never blocks boot). Three real-protocol bugs fixed in the shared SigV4 client: SignedHeaders must be lowercase, the signature was computed over the canonical request instead of the StringToSign, and http.client-injected Accept-Encoding/Content-Length headers were unsigned (MinIO rejects all three). Verified HEAD/PUT/GET/HEAD-object 200 against a live MinIO. `make minio` (Bitnami images: MinIO yanked its Docker Hub repos; quay anonymous is 401) + `make start` chains the sidecar. **Move-in (G24) now requires the harness and object storage gates**, with actionable per-check detail strings; e2e test boots the real app with a fake S3 + controlled Hermes home.
- **Harness onboarding rung (G27):** `POST /api/v1/office/onboard` — CHO-authored registration of a harness employee: upsert, bind + verify the native identity, activate the lifecycle, return the observed presence row. Re-onboard refreshes a binding; the storage-layer native-identity uniqueness guard refuses impersonation (409). The org-side half of harness onboarding — presence (HERMES_HOME mount) is the other.
