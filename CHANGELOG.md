# Changelog

All notable changes to **Pixel Startup** (formerly "Pixel Office"; the visual environment keeps that name) are documented here.
Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions follow [SemVer](https://semver.org/).

## [Unreleased]

### Added
- **G31 Phase 2 (health dimensions, CHO resolver, scene manifest):** `dimensions()` adds three independent, evidence-backed projections — execution (per commitments), attention (required/waiting/clear from the responsibility model), outcome (**only** `evidence` edges prove results; completed work without outcome records is *unproven*, and a negative result with evidence counts as evidence, never failure). Five health states with tested rules: `blocked`, `waiting-external`, `recovering` (unpause stamps `resumed_at`), `stable`, `unknown`, each with a shape-distinct 16×16 sprite and a deterministic generator. `GET /api/v1/scene` (versioned manifest, schema v1, state ETag + 304): the CHO-mode resolver — curious surfaces idea seeds, focused summarizes them, driven adds bounded decision stations with impact counts; capability components are `verified | suggestion | unavailable` (never fabricated availability); layout positions derive from node ids so minor updates never rearrange the scene; 50 projects render as 10 workstations + one count summary; household scope never leaks. Zero LLM asserted across graph/scene/impact reads.
- **G31 Phase 1 (census, truth model, attention, dependency impact):** measured repository baseline (`docs/g31-baseline.md` — office renders a full scene redraw ~16 fps idle on one 2d canvas; graph API 21–55 ms; no WebGL anywhere). Schema v7 extends the organizational vocabulary (decision/commitment/contact/capability/outcome) with an `owner_role` (cho/employee/client/vendor/external) and `soft_depends` edges — migration rebuilds the graph tables from staging copies and preserves all rows (tested). `attention()` gives responsibility-aware states: CHO/employee overdue commitments become actionable-overdue, client/vendor/external silence is only `waiting` (never a failure), explicit follow-up policies (`days`/`business_days`) create follow-up opportunities at threshold, paused work is dormant, unknown data stays unknown. `GET /api/v1/graph/impact` surfaces a shared blocker ONCE with direct/downstream-affected counts and soft-dep scheduling risks — separate outputs, cycle-safe, scope-isolated. Zero LLM calls maintained (tests assert).
- **Living Startup environment (G30):** organizational graph in SQLite v6 (organization/goal/idea/project/milestone/task; depends_on/related/evidence edges; stable ids; company/household scope isolation; idempotent, cycle-guarded edges via `POST /api/v1/graph/edges`). Deterministic health projection (`src/pixel_startup/graph/health.py`, zero LLM calls — asserted): seed/growing/thriving/needs-attention/withering/dormant/completed/archived, each with a human explanation; deadline-free ideas never rot, paused work never deteriorates, completed work never rots, blockers are named. `docs/g30-living-startup.md` carries the API. Dashboard gains a **Living Startup** tab: lazy-opened (data + sprites only when the view opens), SVG mind map with pan/zoom/drag, persistent branch collapse, select→detail panel, stalled-work panel, plant-seed form, connect-related form, CHO-policy (`startup.mood`: curious/focused/driven) banner — view preferences, not separate data models.
- **Resource discipline (G32):** `GET /api/v1/graph` answers a state-summarizing ETag + **304** to `If-None-Match` (frontend reuses the tag; unchanged state = zero payload, zero re-render), and both frontends degrade gracefully — `prefers-reduced-motion` collapses animation and constrained devices (`hardwareConcurrency`/`deviceMemory`) get a `.pixel-lite` mode that drops animation/filters before informational fidelity. Full table + design evidence in `docs/g32-resource-discipline.md`.
- **MinIO connected + real SigV4 (G29):** storage provider probe (HEAD bucket) promotes the minio row at boot, and every startup appends one JSONL access-log line to `shared/access-logs/<date>.jsonl` (storage down never blocks boot). Three real-protocol bugs fixed in the shared SigV4 client: SignedHeaders must be lowercase, the signature was computed over the canonical request instead of the StringToSign, and http.client-injected Accept-Encoding/Content-Length headers were unsigned (MinIO rejects all three). Verified HEAD/PUT/GET/HEAD-object 200 against a live MinIO. `make minio` (Bitnami images: MinIO yanked its Docker Hub repos; quay anonymous is 401) + `make start` chains the sidecar. **Move-in (G24) now requires the harness and object storage gates**, with actionable per-check detail strings; e2e test boots the real app with a fake S3 + controlled Hermes home.
- **Harness onboarding rung (G27):** `POST /api/v1/office/onboard` — CHO-authored registration of a harness employee: upsert, bind + verify the native identity, activate the lifecycle, return the observed presence row. Re-onboard refreshes a binding; the storage-layer native-identity uniqueness guard refuses impersonation (409). The org-side half of harness onboarding — presence (HERMES_HOME mount) is the other.
- **Office HUD collapse (G28):** `◱ HUD` toggle in the office overlay hides the HUD chrome (timer, chips, login, version) except itself; persisted via localStorage. Dashboard backend strip groups into **Email / Communication / Memory & Storage** buckets over the same `/api/v1/health/services` rows.
- **Move-in readiness (G24):** `GET /api/move-in` — honest checklist: chief human present (Ghostface, Owner, on duty — roster invariant now enforced on every config save; empty `agents`/`rooms` payloads no longer wipe the roster), startup direction set, ≥1 goal; direction + goals persist via `POST /api/config` `startup` (no-erase merge). Dashboard: "Startup & Move-in" card (checklist, direction, goals) + server-truth auto-unlock via `GET /api/auth/check` (admin `pixel_session` shared with the office owner login). Office HUD shows the platform version from public `GET /api/version`.
- **Silicon Garage office environment:** fifth original flat pack (`garage` — the silicon-valley startup garage: whiteboard, neon sign, roller shutter, string lights, server rack, pizza boxes; bare concrete floor) via `tools/generate-environments.py` (+ decor branch, palette), deterministic like the others — shared collision topology, `validate:` BFS nav green; `tests/api-baseline.js` count 4→5 + pack-asset loop.
- **CI publishes the image:** `.github/workflows/python-image.yml` — full python gate (pytest, ruff, pyright, pip-audit) + node gate, then build/push `ghcr.io/bageera/pixel-startup-backend` (`main` + `latest`; `v*` tag → semver + `latest`) with `GITHUB_TOKEN` only, gha build cache; repo default workflow token flipped to read/write. CI also caught three test-hermeticity bugs (host-dependent `~/.hermes` probes) — fixed via a fabricated controlled Hermes home (python conftest fixture + node `HERMES_HOME`).

### Changed
- **README rewritten for the v1.2.0 reality:** python backend first (uv/uvicorn run steps), the 🧑‍💼 onboarding checklist (secrets keys per integration + A2A enable), backend API table (chief/delegate routes), environments section, CI deploy notes; node-era deploy prose retired to the CI publish flow.
- **Capability federation (G23, architectural rule):** "Pixel Startup is the organization; OpenClaw and Hermes are the workforce" — `GET /api/v1/federation/manifest` + `POST /api/v1/federation/events` (idempotent by event id, CHO approval via the plan gate, honest onboarding-gap failures). Pixel consumes sanitized harness events; it does not re-retrieve or re-classify harness-owned work. No second email/memory/messaging engine.
- **Dashboard on native api/v1 (G26):** the editor surface (config/rooms/collision/move-in/version/auth-check) is served natively by the python backend at `/api/v1/*` (same byte-parity stores, no node proxy hop); dashboard.html speaks v1 first with legacy-compat fallback for node-only dev mode. OfficeState parity upgraded to post-G24 semantics (wipe guards, Ghostface invariant, startup no-erase) for both surfaces.
- **Local-dev stack lifecycle (Makefile):** `make start` builds the python image from source (cached) and runs it with `.env`, the `data/` volume and the Hermes presence mount (host uid — the container uid could not write the mounted data dir; `PIXEL_HERMES_LIVENESS=file` on Docker Desktop where the VM cannot see macOS pids), `make stop`/`make restart`/`make pull` complete the loop; `build`/`push-image` now target `Dockerfile.python`.
- **LiteLLM probe evidence (G18 promotion):** cheap unauthenticated `/health/liveliness` probe with a live GET transport (synthetic-client contract unchanged); infra registration promotes probe-qualified providers at boot — the litellm row flips qualified/connected on a reachable proxy. `LITELLM_API_KEY` is still required for `chat.completions`; reachability and model auth stay separate concerns.
- **Dashboard modernized (G25):** 32-bit chrome over the 8-bit pixel art layer — truecolor depth (alpha/glass/gradients/glow) via one CSS-variable theme (deep-space background, sky→violet accents); sprites and the collision grid stay `image-rendering: pixelated`; fixed the `scrolelbar` typo. New backend ops strip reads the api/v1 surface (`GET /api/v1/health/services` + `GET /api/v1/office/state`) and degrades honestly to "python backend not reachable" in node-only dev mode.

## [1.2.0] - 2026-11-21

### Added
- **Chief of Staff rails (G23 steps 1-3b):** python-native LiteLLM `chat.completions` (env aliases honor the node deployment's names); `GET /api/v1/chief/advise` (office state + public repo context, honest degradation); delegated tasks can gate on `payload.plan_required` — `planning` status + pending approval, `GET /api/v1/delegate/{id}/plan` (LLM draft), owner-only `POST /api/v1/delegate/{id}/review` (approvals-row record is the only authorization; Mattermost is the notification surface when configured); verify-before-done via independent re-poll (`verified` status / verbatim divergent verdict, never a re-dispatch).
- **Mechanic Shop / Pirate Ship / Lost Boys Treehouse packs (G22 B3):** three isometric launch environments through the shared generator pipeline — `mechanic_layout`, `pirate_layout`, `treehouse_layout` + `PACK_META`/`LAYOUTS` registry in `tools/generate_environments.py` (generic `build_pack` for all packs; zero backend changes to register new ones). Each: 7 rooms, 16 workstations, 4 interaction spots, themed furniture (workbenches + tool partitions + crate lift platforms; helmsman's wheel, rudder housing, barrels, cargo crates; log walls, lookouts, tree perches) and per-pack palettes with brightened wall-dark for backdrop contrast. Label-pill anchors spaced so iso-adjacent rooms don't collide after projection; partition height 96→72 synced in both the generator and `environments.js`. Test suite extended to 60 asserts: static 4-pack manifest validation, built-in pack switching round (mechanic-shop), registry-count updates.

- **Isometric environment system (G22 B1/B2):** reusable environment manifests (`assets/environments/<id>/manifest.json`, schema 1) validated by `environments.js`; generic pack registry — new packs drop in as directories with no backend changes. New APIs: `GET /api/environments` (list + active + default), `GET /api/environment` (active manifest), `GET /api/environment/:id/manifest`, `POST /api/environment` (auth; selection persisted to `data/environment.json`, survives restart with graceful fallback to `continental` when a pack is deleted). Painted-map endpoints (`/api/collision`, `/api/rooms`) now serve manifest-baked data for non-default environments; dashboard painting/editing stays bound to the default environment (409 otherwise). Packs carry an optional `presentation` block (`projection: isometric`, tile 28×14, origin, wall height), a validated `furniture` taxonomy (kinds + solid-tile rule) that drives rendering and depth sorting, per-environment collision (18×22), 7 named rooms, 16 workstations, 4 interaction spots, spawn and agent-room placement slots. Backdrops are deterministic programmatic renders (`tools/generate_environments.py --check|--only <id>`): Habbo-style cutaway (camera-facing walls become a gold floor curb), continuous ziggurat cornices, room-tinted floors — original generated art, no copyrighted assets. Suite `tests/environments.js` (33 asserts) added to `npm test`.

### Changed
- **Project reorientation (G−1):** platform identity moves from Pixel Office to **Pixel Startup** — repository/package `pixel-startup`, future Python package `pixel_startup`, CLI `pixel-startup`. The visual environment keeps the **Pixel Office** name; character identities, sprites, data file formats (`pixel_actions.jsonl`, `pixel-config.json`, …), API routes, the `pixel_session` cookie and the Vaultwarden device identifier are unchanged for backward compatibility. GitHub repository renamed to `bageera/pixel-startup` (2026-11-20, owner-authorized; GitHub redirects all old-name URLs).

### Fixed
- **Agent-harness presence (Hermes + OpenClaw chips):** `GET /api/presence` is now auth-gated (dashboard cookie or Bearer token) — anonymous callers get 401, since the payload includes session ids/pids; the frontend chips render live state for logged-in users and stay offline for anonymous visitors. `integrations.js` gains `HERMES_PRESENCE_TRUST_FILES=1` for containerized consumers: pods have their own PID namespace (host PIDs unverifiable via `kill(pid,0)`), so liveness derives from `gateway_state.json`/`active_sessions.json` content bounded by mtime freshness checks (5 min for the heartbeat-rewritten gateway file, 30 min for the event-driven session lease file whose staleness is bounded by Hermes' lease GC) instead of host PID probes.
- **`dashboard.html` was inert** (corrupt token spellings shipped in 14fb96e): 18 `onclickk` → `onclick` handlers (Export/Import/Save/Logout/tabs/minimap/brushes), 27 `transiten` → `transition`, 5 `positen` → `position` CSS, `.clickk()`/`clickkX/Y`/`handleMinimapClickk` fixed, and the `rolee` → `role` data-field corruption restored (role inputs round-trip correctly now).
- **`char_2.png` (Charon) was a 631-byte stub** since 14fb96e; the intact 5,221-byte sheet was recovered from git history (075e1f1) and kept as `char_2_original.png`.

### Added
- **Isometric environment system (G22):** four original environment packs (The Continental — default, Backline Mechanic Shop, Inferno Deck, Lost Pines Treehouse) with manifest-driven loading, dashboard environment selector, selection persistence through `POST /api/config` + Python `GET/PUT /api/environment` (SQLite `app_settings`), on-demand asset decode, and graceful fallback to the legacy office. New packs drop into `assets/environments/` with no backend change. See `docs/environments.md`.
- **Python migration gauntlet (G7–G9):** OpenClaw adapter (`/v1/models` only; undocumented ops explicit `supported:false`), Hermes adapter (live filesystem interface — gateway/session/platform discovery, evidence-gated promotion), employee/character alignment (SQLite schema v2: binding-proof chain with storage-layer impersonation guard, CAS lifecycle machine, boot-time non-destructive roster alignment; Charon's OpenClaw binding stays pending the gateway). Details: `docs/migration/MIGRATION-LEDGER.md`.

- **Real pixel-art office placeholder** replacing the blank-grid background: 640x800 (true canvas size — the old 960x720 asset overfilled and clipped), drawn from the default collision map (brick walls, desks/shelves/counter with cyan LED strip, doors, chairs, plants, wall lamps, room tints aligned to Reception/Workstations/Archives anchors). Regenerate with `tools/generate-assets.py` after editing the layout.

### Added
- **First-class agent runtimes**: `GET /api/presence` with Hermes Agent (session/gateway state under `~/.hermes`) and OpenClaw (gateway HTTP probe) adapters in `integrations.js`; live status chips in the office overlay.
- Bilingual UI (English/Spanish) with a persisted language toggle (`i18n` block in `index.html`).
- `Makefile` for Docker build/run/test lifecycle plus `.dockerignore` (keeps `.env`, `data/`, `node_modules` out of the image); `make push-image` publishes to `ghcr.io/bageera/pixel-startup:latest` for build hosts.
- `npm test` now runs the presence-integration, API-baseline (44 asserts) and security regression suites.

### Security
- **Static serving restricted to an explicit public allowlist** (previously the repository root was served — `.env` and source were downloadable).
- **Session authentication**: `POST /api/auth/login` now issues an HttpOnly HMAC-signed cookie; mutating and sensitive APIs require it; automation uses `Bearer PIXEL_API_TOKEN`. Default password `pixeladmin` removed; boot refuses to start without `DASHBOARD_PASSWORD` unless `PIXEL_ALLOW_NO_PASSWORD=1`. Login attempts rate-limited.
- **Raw Vaultwarden item retrieval disabled** (returned passwords to any caller) — returns 403 until the capability executor replaces it.
- **External email send disabled** until authorized draft-first delivery ships.
- **Contacts/org search disabled** (SQL→shell injection class); AI proxy hardened (client system prompts ignored, gated).
